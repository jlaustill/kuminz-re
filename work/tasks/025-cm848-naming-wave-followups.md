## pci-tx2-rx3 — PCI 0x35 status word and RX 0x1A

TX[2] header 0x35 is the ECM status broadcast that the DR cluster / front control module / BCM / SKIM read (DRB 35-00-FF decodes name most bits). Byte 1: immobilizer key valid / speed control on / override / automatic / output request 4 or P1221-P1223 / water in fuel. Byte 2: speed control engaged / OK to lock doors / brake / A/C clutch disabled / in gear / manual. Rebuilt each pass and on a park-neutral switch change - sent at once when the word changes. RX[3] 0x1A is a speed control status broadcast (byte 3 bit 0 engaged / bit 1 on / bit 3 override) from a module that owns speed control: relayed only until the ECM learns its own switches; not received here.

**Open questions**
- Likely firmware slip: with speed_control_switches_learned_flag set the builder tests speed_control_last_cutout_reason (0x40b20a - only 1-12 after boot) so 0x35 byte 1 bit 3 (override) is always 1 and byte 2 bit 0 (engaged) is never set; speed_control_denied_status (0x40b20c: 0 ready / 13 engaged) looks like the intended source. Bench test: sniff 0x35 with cruise set (expect byte 1 = 0x2D and byte 2 bit 0 = 0) and check whether the cluster CRUISE lamp lights.
- Byte 1 bit 6 identity: it is output request 4 (0x40c080 bit 4 - set by the diag_iat_* sequence that also drives requests 43 / 44 = output lines 130 / 131 - and itself has no output line) OR fault word 3 bits 9-12 (DTC slots 162 / 163 / 158 / 164 = P1221 / P1222 / unassigned / P1223 set by the engine_camTiming / engine_camSync checks). Probably the cluster WAIT TO START lamp - confirm by sniffing 0x35 during a cold key-on preheat. protection_fault_latch_flag (0x40b214) is that fault OR - recomputed each pass and not a latch - left unrenamed.

## pci-tx5 — PCI 0x53 warning bits and 0x98 bit 4

PCI TX[5] header 0x53 is a 2-byte ECM engine warning broadcast built every 200 ms by 0x3c5f0 and sent at once on change (else every 1 s): byte 1 bit 5 = a timed alert that 0x513200 starts on a rising edge of coolant overheat / low oil pressure / coolant class B / sensor channel 15 fault / safety_bits_1 9-12 latch (6/6/1/5/10 s derived; 255 = hold); bit 4 = coolant time-at-temperature overheat or low oil pressure; byte 2 = 0. PCI 0x98 bit 4 is 1 and goes 0 while low range is detected: output shaft speed per vehicle speed above 80 rpm per mph (2x the learned 40.2) or the engine RPM per mph detector (off here).

**Open questions**
- Which cluster indicator or chime the two 0x53 bits drive is not provable from the ECM (mydb has no 0x53 or 0x98 rows). Bit 4 matches the CHECK GAUGES conditions (coolant overheat or low oil pressure); bit 5 looks like a timed chime or flash request. Inject 0x53 frames with bit 4 or bit 5 at the cluster to confirm.
- The seconds are derived: PIT PITC 4999 (5 ms tick, consistent with PCI timers aging 10 per 10 ms group-B call) x 40 phases = 200 ms per cm848_updateEngineWarningFlags call. Confirm with a timed PCI capture of the 0x53 bit 5 pulse.
- Comment refresh (names kept): 0x0003c044 cm848_buildPciTransmitMessage12StatusBits and 0x0040b409 pci_transmit_message_12_status_bits should say bit 4 = 1 in high range / 0 while low range is detected (condition_flags_1 bit 2 or low_range_detected_by_engine_speed_flag). Their current text names protection_condition_cleared_flag, which this unit renames. The protection_condition_flags_t condition_flags_1 field comment should record bit 2 = low range from the output shaft ratio.
- protection_condition_flags_t threshold_current bit 5 is the output shaft speed sensor rationality fault: cm848_processEngineConditionFlags sets it when the vehicle is moving but fuel_flow_ema (the sensor-only output speed EMA) stays low, and cm848_calculateTransmissionOutputShaftSpeed then substitutes vehicle_speed x learned ratio. The cruise_debounce_* names in that function are wrong. Not renamed here.
- Stale siblings of the output shaft chain, not renamed: fuel_flow_calculation 0x3fb508 is typed dword but is the raw sensor speed word (0x3fb50a is the EMA state of transmission_output_shaft_speed_in_use); fuel_flow_ema 0x40b636; fuel_consumption_accumulator 0x40b632 = the 2 x 60e6 / 23 numerator; fuel_flow_rate_divisor 0x40b62c = period in us; fuel_injection_delay_timer 0x3fb506 = pulse timeout. fuel_flow_rate_max_cal / fuel_flow_default_cal / fuel_flow_divisor_*_cal / timer_frequency_base_cal / fuel_flow_rate_temp_scale_cal are ROM copies with a wrong _cal.

## pci-tx3-rx4 — PCI 0xB0 and RX 0x2D

PCI 0xB0 (TX[3]) is the ECM's MIL and DTC display request to the instrument cluster. DRB: B0 byte 1 bit 0x80 = CHECK ENGINE LAMP. The cluster (node 0x60) acks it in-frame with 0x60. The builder sets bit 7 (MIL) from the fault MIL request or the RX[8] request. With the engine stopped it forces the MIL on after ~15 s. Bit 6 + bytes 2-3 step through the active then previously active DTCs (BCD from obd_dtc_code_table) after 2 more key-off edges (key on-off-on-off-on). RX[4] 0x2D is the cluster's lamp report (2D <node> <bits>). A missing 0x2D sets P1652 (slot 14). Bits 0x08 / 0x10 for node 0x10 set P0381 wait to start lamp (slot 15).

**Open questions**

## pci-security — PCI 4F C0 / 3F / 4F 10 exchange

The PCI (J1850) 4F C0 / 3F / 4F 10 exchange is the Chrysler SKIM immobilizer handshake. On command 0x80 the ECM makes a session seed (sent on 3F) and computes an expected key by folding the seed with VIN characters 9/14/16/17; on command 0 it compares the key the module returns. A match sets a valid-key flag that drives the PCI 0x35 OK-to-start bit; after a wait with no match the ECM forces governor mode 0x29 and zeroes fuel. The 5-byte shared secret in EEPROM 0x3fee2c-0x3fee30 is streamed back on 4F 10. Blank-VIN and blank-key checks raise DTC P0630 (VIN not programmed) and P0633 (SKIM key not programmed). ## transmission-control — 48RE transmission control

The 0x2f860-0x35328 protection_* cluster plus Bank-2 0x510520 / 0x511b64 / 0x51ab70-0x51cc00 is the ECM's 48RE transmission controller. It turns the TPU-B channel 14 output speed sensor into output shaft speed, infers the current gear 1-4 from the engine / output ratio, decodes the PCI 0x37 shift lever into a J1939-style selected gear and a park/neutral flag (the cruise-fix flag), runs governor pressure (a target per cold / standstill / normal / WOT / 4-low mode with a PID on the slot-102 sensor driving a 671 Hz solenoid), converter clutch lockup (logical output 18), overdrive 3-4 shifts and the O/D-off switch (output 17), and monitors P1756 / P1757 / P1762 / P1740.

## switch-31 — switch 0 / switch 31 state machine

0x2c180-0x2c6c4 is a Cummins pedal-press switch emulator plus two switch-31 consumers. Switch 0 = ignition key switch (line 128 = mios_key_off_detection bit 15; its falling edges feed a key-off count). Switch 31 has no hardware line: every switch function this Dodge build leaves unwired compiles to it (CCVS1 cruise / idle / test-mode fields, PTO set-resume, two-speed axle, derate override, governor type, torque limit). Its only direct writer: with key on + engine not running + j1939_feature_enable_flags bit 10 (0 here = off), three presses past 70 percent and back below 30 percent within 50 passes (5 s) pulse switch 31 for one 100 ms pass; an accelerator sensor fault (bit 11) holds it on.
