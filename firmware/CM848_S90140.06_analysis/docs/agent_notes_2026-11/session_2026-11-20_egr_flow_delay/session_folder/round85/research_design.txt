FIX DESIGN: CM550 2-BYTE STACK ARGUMENTS (read-only; no repository file changed, no build run)

## 0. Summary

**Decision.** `ApplyFunctionDefinitions` gives every typed CM550 parameter custom storage (`FunctionUpdateType.CUSTOM_STORAGE`). It computes each offset from the declared types with the compiler's rule:
- start at +4;
- each 1- or 2-byte type takes one 2-byte slot, right-justified, so a byte sits at slot+1;
- a 4-byte type takes the next 4 bytes, with no alignment padding.

**Gate.** A new CM550-only data file, `output/stack_parameter_layout.csv`, turns this on. `common.sh` `cmd_export` passes the file as `args[1]` only when it exists. CM848 has no such file, so it keeps today's code path.

**Rejected alternatives.**
- An `align="2"` prototype extension cannot place a long at +6 or +10, because of the typeAlign rule. Eleven callees need that (`exponentialMovingAverage`, `cm550_coreTableInterpolation`, `cm550_diagnosticMemoryAddressResolver`, ...). It would also print `__name` in every signature and in `firmware_functions.hpp`, and it needs an install stage.
- A per-row storage column would repeat the ABI by hand on every row.

**Atomic commit.** The code, the switch file and the wave-0 rows (section 3) must land in one commit. Either half alone regresses:
- the switch alone moves four names onto the wrong argument and keeps `in_stack_00000004` in nine byte rows;
- the rows alone cannot place their new types.

**Ghidra 12.2 source facts I checked myself** (zips extracted to `/home/linux/.claude/jobs/374b0424/tmp/w15/r85/research/fix-design/src`):
- **Storage is kept exactly.** `ParameterImpl(name, dt, stackOffset, program)` builds `Varnode(stack:offset, dtLength)` with no justification (`VariableImpl.computeStorage`). `FunctionVariables.updateFunction` keeps a custom storage when the resolved length equals the storage size (`getResolvedVariable`).
- **The return storage stays the same.** `FunctionDB.updateFunction` calls `setCustomVariableStorage(true)` first, and that freezes the current dynamic return storage. `setReturnType` runs before it in the script (line 242), so D0 is computed first. An `undefined` return gets no dynamic storage (`PrototypeModel.getStorageLocations` note), so the frozen and the dynamic encodings are the same.
- **The custom flag is output-neutral.** In the decompiler C++ it is read only by `ActionPrototypeWarnings`, and only when the model is unknown (grep over all `.cc` files).
- **The callee keeps the locked parameter.** `FuncProto::unjustifiedInputParam` returns false for a read that is properly contained in a locked parameter, so nothing is widened. A read outside every locked parameter is not widened either, and renders as `in_stack_` (detectable).
- **Each call site loads at the parameter's own offset.** `ActionFuncLink::funcLinkInput` does `opStackLoad` at each locked stack parameter's own offset.
- **Callee shells carry the stored storage.** `LocalSymbolMap.grabFromFunction` sends `var.getVariableStorage()` with typelock set when the signature source is not DEFAULT, for callee shells too.
- **Hazard.** `HighFunctionDBUtil.updateDBVariable` on a parameter of a custom-storage function re-sizes it with `resizeStorage`. So never retype a CM550 parameter through `local_variables.csv`.

**`firmware/scripts/ScriptUtils.java`** (pure, testable):
```java
+    // ── Stack parameter layout ───────────────────────────────────────────────
+    /** A firmware's stack parameter layout (stack_parameter_layout.csv). */
+    public static final class StackParameterLayout {
+        public final String language; public final int firstOffset; public final int slotSize;
+        public StackParameterLayout(String l, int f, int s) { language = l; firstOffset = f; slotSize = s; }
+    }
+    /** setting,value[,comment] rows; header and '#' lines skipped; needs language, first_stack_offset,
+     *  slot_size (2 or 4); an unknown setting is an error, so a typo cannot pass silently. */
+    public static StackParameterLayout parseStackParameterLayout(List<String> lines) {
+        String language = null; Integer first = null, slot = null; boolean header = true;
+        for (String raw : lines) {
+            String line = raw.trim();
+            if (header) { header = false; continue; }
+            if (line.isEmpty() || line.startsWith("#")) continue;
+            String[] p = parseCSVLine(line);
+            if (p.length < 2) throw new IllegalArgumentException("bad row: " + line);
+            switch (p[0].trim()) {
+                case "language": language = p[1].trim(); break;
+                case "first_stack_offset": first = Integer.parseInt(p[1].trim()); break;
+                case "slot_size": slot = Integer.parseInt(p[1].trim()); break;
+                default: throw new IllegalArgumentException("unknown setting '" + p[0].trim() + "'");
+            }
+        }
+        if (language == null || first == null || slot == null)
+            throw new IllegalArgumentException("needs language, first_stack_offset and slot_size");
+        if (slot != 2 && slot != 4) throw new IllegalArgumentException("slot_size must be 2 or 4");
+        if (first < 0 || first % 2 != 0) throw new IllegalArgumentException("first_stack_offset must be even");
+        return new StackParameterLayout(language, first, slot);
+    }
+    /** Offsets in parameter order: the first at firstOffset, each taking ceil(len/slot) slots and
+     *  right-justified in them (big-endian: a byte in a 2-byte slot is at slot+1). No padding for the
+     *  type's alignment (CM550 puts a long at +6 after a word). slotSize 4 reproduces 68000.cspec
+     *  __stdcall (align 4, right-justified; its size map caps alignment at 4) for 1/2/4/8-byte types. */
+    public static int[] packStackParameters(int[] lengths, int firstOffset, int slotSize) {
+        int[] offsets = new int[lengths.length]; int next = firstOffset;
+        for (int i = 0; i < lengths.length; i++) {
+            if (lengths[i] <= 0) throw new IllegalArgumentException("parameter " + i + " has no fixed length");
+            int space = (lengths[i] + slotSize - 1) / slotSize * slotSize;
+            offsets[i] = next + space - lengths[i];
+            next += space;
+        }
+        return offsets;
+    }
```

**What would show the fix is wrong:**
- T1 or T2 differs.
- A token remains exactly at a row's storage. That means the decompiler does not honor a locked unjustified stack parameter, and the premise fails. A token elsewhere only means the row is incomplete.
- A call constant differs from the push, or a stale `uVarN` remains. That means a wrong offset, or a deferred pop that breaks the load.
- A re-indexed name lands on the other argument.
- A quiet control function changes.
