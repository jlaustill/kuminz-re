- BOOT_DIAGNOSTIC_RESULT (size 4), the boot kernel's twin of J1939_DIAGNOSTIC_RESULT. Its 11 codes are named from
  their producers in the boot kernel.
  - The application's 0 / 2 / 3 / 4 / 8 / 9 / 10 / 0x1a mean the same here; 10 also covers the dispatcher refusing
    a ROM handler while the low nibble of eeprom_service_mode_flags is set.
  - Its own:
    - 5 UNKNOWN_SERVICE: the dispatcher's default; the application uses 0x18;
    - 0x11 FLASH_WRITE_FAILED: cm848_writeBootDiagnosticMemory, a flash write at an odd address or a failed flash
      write;
    - 0x17 EEPROM_TRANSFER_NOT_STARTED: service 2, when mpc555_initEepromTransfer returns 0.
  - 0xff (nothing to send) is no member, as in the application enum: the dispatcher masks each result with 0xff.
  - Typed on cm848_validateDiagnosticRequestLengthAndAuthorization's return. Its full prototype also takes
    j1939_rx_msg_t *request, so the validator reads request->data_length / data_pointer.
  - Typed on the boot dispatcher's result_code local (keyed BVar4, the positional name with the type's prefix,
    from round 64's lesson), and its entry local is named.
  - Applied on the first build:
    - the dispatcher reads result_code = BOOT_DIAGNOSTIC_RESULT_UNKNOWN_SERVICE / _REGION_REFUSED;
    - the validator returns _WRONG_LENGTH / _KEY_MISSING / _KEY_REFUSED.
  - cm848_handleBootExecuteAtAddressService takes the enum return by inference. Its region check now reads
    != BOOT_DIAGNOSTIC_RESULT_UNMAPPED_ADDRESS (9 = no region) and gains & 0xff masks.
