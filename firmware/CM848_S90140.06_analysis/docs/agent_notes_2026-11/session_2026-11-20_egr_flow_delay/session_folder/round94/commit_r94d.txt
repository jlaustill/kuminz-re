mc68k_initializeSerialEepromDriverAndLoadMirror (0x26854) sets the start-up load length first and the refresh length
after the load:
  0x2694a  move.l #0x804f94,d0 / subi.l #0x803b08,d0 / addi.w #-2,d0 / move.w d0,(a2)   -> 0x148a (a2 = 0x801a88)
  0x269da  move.l #0x804156,d0 / subi.l #0x803b08,d0 / addi.w #-2,d0 / move.w d0,(a2)   -> 0x64c
So RAM 0x803b0a-0x804f93 is EEPROM 0x0-0x1489, loaded at every start-up, and only 0x0-0x64b is refreshed afterwards.
Round 73 had set the CM550 _cal window to the refresh (0x803b0a-0x804155). CM848's window is its whole start-up
load (0x3fd482-0x3feec1 = 0x1a40 bytes; its refresh is 0x8e8), so CM550's window is the whole load too. The rows past
offset 0x1000 are non-volatile records (fault code lists, InSite statistics, trending), and the parameter ID table
tags EEPROM 0x72a + 2n for j1939_input_signal_timeouts.
