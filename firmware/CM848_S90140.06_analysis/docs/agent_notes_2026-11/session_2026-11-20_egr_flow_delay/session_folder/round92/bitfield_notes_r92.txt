LOGICAL INPUT RULE (also covers words 13 and 14, outside this batch): logical input k has
- status byte 0x80bcce + k/8, bit k%8 (e2m 000E + k/8)

- priority 0x80bd4a + k (e2m 12A8 + k)
- enable = table bit 208 + k = word 13 + k/16, bit k%16. On this big-endian CPU the mask byte for inputs 8j..8j+7 is 0x803cae + 2*(j/2) + (1 - j%2).
cm550_FUN_00020890 uses the rule for the 17-entry j1939_input_signal_descriptor_table (ROM 0x20108). Logical inputs: 72 9 54 11 10 3 1 2 14 13 60 56 58 20 19 15 54. cm550_FUN_000206a8(k, j) is called with (0x36,1) (0x36,4) (0x21,6) (0x20,0) (0x36,2). Words 15-17 map as follows:

== W4
Method: every abs.l reference to 0x803cc6-0x803cd7 in J90350.00.rom.bin (scratch hits68k.py), each hand-decoded. All 20 are move.w (abs).l,d0 + andi #single-bit-mask + branch. No writes, no odd-byte (btst) or long accesses, no tst. Indexed accesses from word 0 (movea.l #0x803c94,a0) reach only words 7-9 (bit 112+4n), words 13-14 (logical switch + 0xd0, cm550_FUN_000206a8 / cm550_FUN_00020890) and word 26 (bit 416+n, the two derate loops). llvm-mc-18 drops clr / addq / andi / moveq on m68k and loses address sync, so it is not reliable for whole functions here.

'No test' always means none in the dumped 256 KB. 109 call targets above 0x40000 are undumped, and the bench EEPROM sets bits nothing in the dump tests: word 25 0x0180, word 27 bit 13, word 32 bits 6 / 12 / 13.

Bench EEPROM and RAM mirror agree: w25 0x0180, w26 0, w27 0x2010, w28 0, w32 0xf241, w33 0. The length word 0x803c92 reads 0x46 (70 bytes = words 0-34).

e2m quirks:
- v64t6_s (and every 5x/6x e2m) files MXLPANEA under +0x36. The code and the 7x/8x files say +0x34.
- EPO3DXEN (word 26 bit 4, 'oil temperature') does not match the code's channel table: channel 4 is water in fuel, and v64t6_s has no EPO3 block.
- Word 27's AHEN / TBAMEN / TBSPTMEN / TUWGEN / TUWGOVEN N records carry two bit numbers (5-9 and 11-15). I followed 5-9 (the leading number and every S-record mask). No CM550 code reads either set.
