Its uniqueness check only fires for one name on two different addresses. 16 distinct addresses, 16 distinct names.

RECORD ARRAY (12A7): 0x80bd1a-0x80bd49 is one byte array of 48 per-output override priorities. Output N is the image bit at 0x80bcf6 + N/8, mask 1 << N%8, so the 6 image bytes 0x80bcf6-0x80bcfb hold 48 outputs (the port_e_output_image comment already says 'override slot 0x80bd1a + output number'). The application writes an output only while its slot is 0 (tst.b slot / bne / clr.b slot / bit op), so the application client is priority 0. cm550_ioControlMaskStateMachine @ 0x24858 indexes the array by output number from the list at 0x611a8: it claims a slot at 0x80 when it holds <= 0x80, then releases it to 0. The other users address it as base register (movea.l #0x80bd1a,a3/a2) + displacement: mc68k_ioDriverStrobeHandler, mc68k_initializeDiscreteOutputDrivers, processProtectionFlagConditions, 0x1ca54, mc68k_runPowerDownSequence and mc68k_applicationMain (slot 0x13). e2m 12A8 is the matching input priority array from 0x80bd4a; its +0x20.. entries are the output feedbacks, and +0x26 = warning lamp. CM848 twin: logical_output_request_priority byte[80] at 0x40c094, the same e2m block 12A7. The names stay flat this wave only because slots 0x80bd1a/1b/21/22/25/38 already have rows. A later wave could make 0x80bd1a byte[48].
