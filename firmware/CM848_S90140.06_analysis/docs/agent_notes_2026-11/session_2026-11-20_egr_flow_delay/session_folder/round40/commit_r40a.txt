audit_cal_suffixes.py's MISSING list (EEPROM-backed names without _cal) drops from 258 to 234.
- **Which rows:** only rows that application code alone uses (missing_users.py) and whose name describes the
  application's EEPROM value.
  - The boot-named rows stay: they sit at addresses the boot kernel uses before the application loads the mirror over
    them. So do the dual-use rows.
  - The region labels stay: eeprom_mirror (EEPROM 0x0, e2m 000B ECM_STAT) and eeprom_checksummed_block_start.

- **Seven names change with the evidence:**
  - lifetime_fuel_used_at_governed_speed -> lifetime_idle_fuel_used_cal (e2m 117F +A Total_Idle_Fuel_Used).
    - The "governed speed" flag is the low speed governor fueling state within +-400 counts (50 rpm) of its reference,
      i.e. idle.
    - So the family follows: lifetime_idle_time_cal, trip_idle_fuel_used_cal, trip_idle_time_cal, and
      engine_at_governed_speed_flag -> engine_idling_flag.
  - governor_speed_target_trim -> low_speed_governor_no_load_fuel_trim_cal: its only use adds it into the no-load fuel.
  - j1939_governor_feature_byte -> feature_selection_bits_cal: a scan-tool-programmed feature bitmap (SCI EEPROM
    setting type 2), not J1939.
    - bit 0 / 1: the cab / remote power take-off governor;
    - bit 2: the oil change monitor;
    - bit 3: the initial overdrive flags;
    - bit 4: the water in fuel sensor's second configuration.
  - sensor_validation_startup_accumulator -> eeprom_verify_retry_lifetime_total_cal: the power-down save adds
    cm848_getEepromVerifyRetryTotal() to it.
  - governor_mode_code_diag_snapshot -> final_fueling_state_before_shutdown_or_excess_injection_fault_cal, next to its
    sibling total_fueling_before_shutdown_or_excess_injection_fault_cal.
  - protection_b_fault_active_flag -> exhaust_brake_switch_learned_flag_cal.
    - It is set once the exhaust brake switch is seen on, which turns on the engine brake 1 output read-back check.
    - The SCI status byte reports it next to four_wheel_drive_switch_learned_flag_cal.
    - Block 1930's offsets drift in 11.46, so the table's BTR_Numerator at that address is not used.
